Free and open source For Claude Code macOS app

Start every day knowing what actually needs you.

Scout is a background agent for Claude Code. Through the day it reads your Slack, email, calendar, tickets and meeting notes, checks them against each other, and leaves you a short list of what needs you, with its sources. It also keeps a knowledge base of plain Markdown files in a folder on your Mac.

Download for Mac Install from the terminal

Runs on your own Claude Code sign-in, with no separate API key. Needs a paid Claude plan. The app needs macOS 15.7 or later.

Who it's for

For people whose work lives in a dozen tools, and who are tired of stitching it together by hand.

Leads, engineers, founders and anyone who starts the morning with Slack, an inbox, a calendar, a tracker and last week's meeting notes, and has to work out which of it matters today.

It's scattered

The thing that matters is half in a Slack thread, half in an email and the rest in a ticket. No tool puts the pieces together.

It goes stale

Notes are out of date a week after you write them. The tracker says "done" while the pull request is still open.

Summaries sound sure

An AI summary reads the same whether three sources agree or one person said it once. You can't tell what to trust.

What it does on its own

A schedule of short runs, every day, without you asking.

Each run is a Claude Code session on your Mac. It reads what changed, cross-checks it, and writes the result to your files as a git commit you can read and undo.

  1. 08:00 weekdays · 08:30 weekends

  2. 11:00 · 13:00 · 17:00 · 19:00

    Look only at what changed since the last run, such as a new reply, a merged pull request or a moved meeting, and update the list.

  3. 14:00 weekdays

    Picks the part of your knowledge base that's thinnest or most out of date and fills it in from the web, docs and your tools.

  4. 18:30 · 22:00

    Dreaming: it reviews its own day

    Reads your 👍 and 👎, logs its mistakes and fixes its own instructions. Small fixes apply directly. Bigger ones become proposals that apply after a few days unless you reject them.

  5. Nightly

    Knowledge base tidy-up

    Rebuilds one overgrown project page a night, so each stays a one-screen summary and the detail moves into linked notes.

  6. Whenever you want

    You, in Claude Code

    /scout-work walks through today's items one at a time and acts only when you say yes. /scout-ask answers questions from your notes.

These are the default times. You can move them, pick the model each run uses, or turn runs off. If your Mac is asleep, missed runs catch up later.

It gets better on its own

Six habits that make tomorrow's Scout better than today's.

Each one is a real part of how Scout runs. Try them: every card below works. The names and items in them are invented.

It keeps a record of its own mistakes

Flag something with 👎 and Scout logs the error, the cause and the fix, then watches whether the fix holds. A “fixed” mistake that comes back is marked as a regression.

Pattern #12regression
errortook a name from a meeting transcript
causedidn't check your people notes first
fixmatch names against people notes before writing
Seen 3 times. The fix goes into its own instructions.

It edits its own instructions, in the open

Each evening it decides what to change about itself. Small fixes apply directly; bigger ones become proposals that apply after a few days unless you reject them. Every change is a git commit you can revert.

proposal · match-names-to-notesapplies in 3 days

Match people against your notes, never a transcript alone. → edits its instructions

dreaming [22:00]: applied proposal match-names-to-notes · git revert any time

It won't guess who someone is

Mixing up two people is the worst mistake a set of notes can make. Scout won't merge, split or rename a person on one source; it holds the question for you.

⏸ Held for you

Is “A. Rivera” someone new, or the Alex already in your notes? One source, so Scout can't tell.

It goes and finds what it's missing

Between briefings it scores which notes are thin or out of date and rotates through your projects. Leave a note in any file and it jumps to the front of the queue.

//==<< check the vendor's new pricing >>==//your note, moved to the front

  2. billing-revamp9 days old
  3. api-migration7 days old
  4. onboarding-flow6 days old
  5. data-pipelinedone ✓

It asks only what it can't find out

Some facts aren't in any tool, like who really owns a decision. Now and then Scout asks one short question, with a link and a one-line summary. Your answer goes into your notes, and it never asks twice.

It works through its own wishlist

Scout keeps a list of improvements to itself and works it down, one item an evening. The Mac Control Center, a terminal view of action items and the research runs all started there. You can add to it too.

What you get

A list you can trust, and notes you can actually read.

Every item says how sure it is.

Scout doesn't take any one tool at its word. A meeting invite is checked against the transcript, a ticket against its pull request. Each item carries a tag, so you can see how much weight to give it.

  • verified: two or more sources agree.
  • single-source: only one says so. It's shown as tentative, never as fact.
  • contradicted: your tools disagree. You see both sides; Scout doesn't pick one.
  • Read it in the app or as a Markdown file, or get a summary by Slack DM or Telegram. Reply 👎 with a one-line fix and Scout learns from it.

A knowledge base in a folder you own.

People, projects and decisions become linked Markdown files in ~/Scout. Open them in any editor or in Obsidian. Every run is a git commit, so you can see what changed and undo it.

  • One-screen project pages. Each project page sticks to a standard: where it stands, what's next, key decisions, open questions and people.
  • Detail in knowledge notes. The long story moves into linked notes, each one cited to a source.
  • Kept that way. The nightly tidy-up rebuilds pages that grew too long, one per night.

Linked, so it can check itself.

People, projects, tasks and meetings are typed notes that link to each other, and every run checks them against a schema. Those links are what let Scout hold one source up against another.

  • Typed, not a pile. A person, a project and a task are different kinds of note with different rules.
  • Every run is a commit. The git history is Scout's memory of what it changed and why, and any of it can be undone.

The Mac app

Set up in minutes. Then it mostly stays out of your way.

Scout.app lives in your menu bar. It shows what Scout found, what's running and whether anything needs you, and it keeps itself and the engine up to date.

Onboarding sets up everything.

  • Checks for Claude Code and, if it's missing, opens Anthropic's installer for you.
  • Installs the Scout engine, registers it with Claude Code, and asks for your name, email, tools and daily budget.
  • Creates your vault (~/Scout by default) and schedules the runs.
  • Updates itself. The app checks for signed updates once a day, and updating the app updates the engine it installed.

It tells you when runs stop working.

Scout keeps a health check of its own runs. When something goes red, such as an expired Claude sign-in, runs that keep failing, or a run type that has quietly stopped producing anything, you get a desktop notification or a Telegram message with the fix, a reminder while it lasts, and a note when it recovers. If you hit your plan's usage limit, runs pause until it resets instead of failing.

You choose the model and the budget.

Every scheduled run is a slot you can set on its own. Keep the morning briefing on Opus and move the catch-up scans to a lighter model, or the other way round.

  • Per-run model choice: Opus, Sonnet or Haiku for each slot.
  • A daily spending cap, a cap per run, and a rolling five-hour limit that skips runs before you hit your plan's ceiling.
  • Backs off after failures, so a broken setup doesn't burn through your usage.

Privacy and trust

Your notes stay on your Mac, and you can check everything it does.

Scout reads some of the most private parts of your work, so privacy is built into how it runs, not added as a setting.

1
Local by defaultNotes, logs and settings are files in ~/Scout and its git history. There's no Scout account, no Scout server and no analytics.
2
Your accounts, your toolsRuns use your own Claude Code sign-in and the tools you've connected. No separate API key, and no keys of yours ever pass through us.
3
Private and local-only notesMark a note or folder private and it stays on surfaces only you see. Local-only folders never leave the Mac, whatever else you turn on.
4
Checked on every commitBefore Scout saves anything, privacy checks look for private text in the wrong place. Scheduled runs get stricter rules than you do. They can't skip the checks, switch them off, or pass themselves off as you to get round them.
5
Open sourceMIT licensed. Read the code, the instructions it runs on, and every change it makes to itself.

Share chosen folders with your team, if you want to

Off unless you set it up. Pick folders or single notes to share with named colleagues or your whole organization, so their AI assistants can search them too. Everything private stays on your Mac, and you can preview exactly what would upload before anything does.

It shows its work, and you can undo it

Every run, and every change Scout makes to its own instructions, is a separate git commit with a readable message. Anything it isn't sure about, especially who someone is, waits for you to confirm.

Tested before every release

Before each release, a test run has Scout update a sample project's notes. The release doesn't ship if the page bloats, turns into a diary, or gains facts without a source.

  2. Drag Scout.app into Applications and open it.
  3. Onboarding does the rest: Claude Code check, engine, your tools, your vault, your schedule.
Download for Mac

Already installed Scout from the terminal? The app picks up your existing setup and leaves it as it is.

No app

From the terminal

Installs the Claude Code plugin and engine, then asks for your details, tools and budget and creates ~/Scout. The engine also runs on Linux.

$ curl -fsSL https://raw.githubusercontent.com/Raven-Scout/Scout/main/install.sh | bash

It installs the latest release, never unreleased work. You don't need Homebrew or Python. Read the script first.

You'll need: Claude Code, installed and signed in, and a paid Claude plan. Max is recommended, because each run is a Claude Code session that counts against your plan's usage (about eight runs on a weekday).

Works with: Slack, Gmail, Google Calendar, Google Drive, Linear, GitHub, Granola, Fathom, WhatsApp and Google Messages, connected through Claude. Scout can also draft a read-only connector for other tools you've connected, and send its summary to Slack or Telegram.

Questions

Good to know

What does it cost?

Scout itself is free and MIT licensed. Its runs use your Claude plan's usage, like any other Claude Code session. A daily cap, a per-run cap and the five-hour limit keep that in check, and you can move any run to a cheaper model.

Does my data go to you?

No. There's nothing for it to go to: no Scout account, server or analytics. To do its work, Scout sends content from your tools to Claude under your own Claude account, and reads the tools you connect under your own sign-ins.

Two things go out over the network on top of that: the Mac app checks GitHub for updates once a day, and, only if you turn on team sharing, the folders you choose upload to the place you link. Details are in the privacy policy.

Do I need the Mac app?

No. The terminal install runs the same engine and the same schedule. The app adds the menu-bar panel, the Control Center, settings, alerts and automatic updates.

What about Windows and Linux?

The app is macOS only (15.7 or later). The engine runs on Linux through the terminal install. There's no Windows support.

Can I undo what it does?

Yes. Your vault is a git repository and every run is a commit, including changes Scout makes to its own instructions. Revert any of them with git revert.

Where do I see the results?

In the Mac app, in the Markdown files in ~/Scout (they open fine in Obsidian), and, if you connect them, in a Slack DM or Telegram message after each run.
