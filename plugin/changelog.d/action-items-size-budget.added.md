- `scoutctl action-items fit` keeps the daily action-items file to its budget, with no model involved and no open task deleted. It moves 🅿️ Parked tasks, and 🟢 Watching and 🟡 tasks not due within 14 days, to `action-items/backlog.md`, and moves backlog tasks back when they come due. Past 80 open tasks it moves the bottom of 🟡 to the backlog. Prose sub-bullets past the first move to each task's context note; a group holding a comment, a nested task, an inline directive or HTML always stays. Completed ✅ Recently Completed entries older than 3 days are deleted from the daily file (git keeps them); an entry holding any open task never is.
- `fit` can be re-run safely and survives a failed write. A task already in the backlog under the same task line is merged in place; under a different task line both copies stay and are reported. Prose already in a note isn't appended again. An unreadable backlog or note stops it before anything is written. Writes go in an order that never leaves an open task in neither file: notes, then the backlog with new arrivals, then the daily file, then the backlog without the tasks that moved back. A manual `--apply` takes the vault's session lock, and `materialize` runs it once a day, logging any failure. Under `action_items.fit: report` (the default for this release) it writes nothing and records what it would do in `.scout-logs/action-items-fit.json`; set `apply` to let it write.
- `scoutctl action-items check-size` checks the daily file against `action_items.budget` in `scout-config.yaml`: a target of 50 KB and 80 open tasks, and a hard limit of 60 KB and 100. Briefings and consolidations run it before committing. Past the target it is a warning plus a 🪵 Run notes line, and `scoutctl bootstrap doctor` warns past the hard limit. Neither ever fails a run.
