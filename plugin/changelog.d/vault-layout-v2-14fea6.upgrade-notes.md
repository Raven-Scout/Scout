- **This release reorganises your vault (layout v2).** The first upgrade on it moves Scout's files into the new folders in two commits: `scout-update: move the vault to layout v2 (N files)` (renames only, so `git log --follow` keeps each file's history) and `… (content)` (path updates, identity notes, the merged meetings registry and a report at `reports/YYYY-MM-DD-layout-v2.md`). Refs `refs/scout/migrations/layout-v2/pre` and `…/post` mark them. Tracked edits go into a checkpoint commit first; untracked files are never added. Files Scout doesn't know in the vault root are never moved. Links in `action-items/archive/` and dated source notes keep their old paths; they still resolve by name.
- **When the move waits.** It defers, changing nothing, while a brain skill merge sidecar is pending (resolve it with `scoutctl bootstrap resolve`), a run is waiting for the session lock, a git merge or rebase is in progress, a file already sits at a target path, a note would come out less private (register a private space with `visibility: private` before the move), or the installed Claude Code plugin is older than this release. Self-update counts a deferral as "not yet", not as a failed attempt, and retries on its next run. `scoutctl vault migrate --plan` shows the move and why it would wait. If a move is interrupted, scheduled runs pause and run health turns red until the next upgrade finishes or undoes it.
- **Compatibility links.** The move leaves symlinks at the old entry points (`scripts`, `hooks`, each root `run-*.sh` and brain skill) so the heartbeat, an older engine's tick and open sessions keep working; the next upgrade that finds the jobs, engine pointer, git hook and installed plugin on the new paths removes them. Restart open Claude Code sessions in the vault after the move.
- **Your own scripts.** `scripts/` and root `run-*.sh` move whole, yours included, with their literal paths rewritten. A script that finds the vault as "the folder above me" is now two levels deeper: the report lists the ones to check by hand.
- **Supported combinations.** Engine, plugin and app at this release or later. An older Scout.app can recreate a v1 record folder (for example `docs/wishlist/`); the next upgrade moves its files to `scout/records/` and reports them. Other git work trees of the vault still hold the old layout and will conflict when merged.
- **Rolling back.** `git revert --no-edit refs/scout/migrations/layout-v2/pre..refs/scout/migrations/layout-v2/post` (the two move commits), then run `scoutctl bootstrap upgrade` with the release before layout v2 (for example from its plugin cache folder) so it reinstalls the jobs, shim and pointer on the old paths. A revert alone doesn't restore the untracked state, the jobs or the pointer.
