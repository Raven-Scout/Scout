- **Scheduled runs keep already-shared notes current, after the privacy check** (`engine/scout/kb/lint_privacy.py`, `phases/core/privacy.md`). Since #569 the commit hook refused every scheduled run's added or reworded line in a note with an effective share, so shared project pages went stale and the review queue filled with edits nothing applied. With the new `privacy.shared_edits: checked` (the default), such a line passes when it passes the scan a note new to a share gets: no link to a private note, no private note's name, title or alias, no quote of a note shared with you. A `%%privacy:allow%%` marker allows none of a run's lines there, as for an outbound send. Still refused in a scheduled run, unchanged: sharing a note more widely, setting or changing its `federation_scope` (narrowing too), adding a marker, making a private note normal, editing the `privacy:` block, and any change to a non-note file in a share (`.csv`, `.xlsx`, …). The check knows private notes only: other material a run writes into a shared note reaches its readers.
- **The nightly KB pass may rebuild a shared project page** (`engine/scout/kb/structure.py`, `phases/modes/kb-deep-work.md`). Under `checked`, `kb structure --next` picks a page with an effective share like any other, as long as no note the rebuild could write (new subfolder notes, new source notes, notes already in the folder) would be shared with someone the page isn't; moving text into a narrower note is fine. When one would be, an over-budget page falls back to trim-only, as before; otherwise it is skipped. A loose file with a share still stays where it is.
