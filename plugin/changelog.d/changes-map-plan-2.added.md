- **The changes map, part 2: verdicts and the phases that act on them.** Each change Scout makes to itself from a scheduled run now gets a before/after test: the 14 days before the change against a review window (14 days by default). The verdict is one of helped, no clear effect, hurt, can't tell, or rolled back. `scoutctl changes --json` works verdicts out again on every read and checks each change row against the vault's git history, so a run can't write its own verdicts or invent a change.
  - Noise now also counts a direct message to the owner with no reply or reaction within 48 hours, and a 🔴 action item left untouched for 3 days (the daily materializer records it once).
  - Owner-only commands: `scoutctl changes approve|reject <id>` for a governance change, `undo <id>` and `wrong <id>` for a change or its verdict, `auto-rollback off|targeted|one-at-a-time` (off by default, and it acts only after the owner marks calibration done), and `calibrated [--reset]`. Scheduled runs are refused. An approval holds only for the diff the owner saw: if the pending change is edited afterwards, it waits for a new decision.
  - Each dreaming run checks `scoutctl changes due --json` and carries out the owner's undos and approved or rejected governance changes. An undo takes back only the lines the change made in its own files, so later edits to other parts of the same file stay and don't block it. Governance edits now wait in `governance-pending/` for the owner's OK, and the old proposals file is gone from the run instructions.
