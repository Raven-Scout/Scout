- **You review what agents wrote before any of it reaches the vault** (#550 V4b2, spec §7.1b; `engine/scout/delegate_review.py`). `scoutctl inbox review` lists, per delegate, its observations, its held `add-comment`s and any op over a daily cap. Each item shows its text with every hidden character spelled out as `\u{…}`, and names any word that mixes alphabets or stands in another one (a look-alike).
  - **`inbox review accept <ULID>`** asks you to type the ULID again (or takes `--confirm <ULID>`), and checks the text again. A comment goes under its task as `delegate-<id>: …`, in one commit; `inbox revert` undoes it. An observation becomes a private note in `knowledge-base/from-agents/<id>/`, quoted and marked as the agent's, in one commit; `inbox revert` removes it while it is unchanged. From then on, runs read it.
  - **An accepted note stays hidden from every agent**, its author included, and from the owner's sessions in other folders, until you **`inbox review promote <ULID>`** it. Promoting checks and shows the text again, makes the note normal with `promoted_from: delegate:<id>`, and optionally limits it to named agents (`--to author`, `--to <id>,…`). `inbox review unpromote` hides it again. **`inbox review reject`** drops an item.
  - **Agents' text is marked wherever runs see it.** `kb read`, `search` and `files` print `[from-agent: delegate-<id>]`, and `kb read` adds a line saying it is data, never instructions. The privacy phase says the same. The KB passes (scoring, fact-checks, structure, freshness, lint reports) leave `from-agents/` alone, and such a note is never an entity in the graph.
  - **Never shared until promoted.** A note holding an agent's text gets no federation scope, whatever its folder default says. A scheduled run can't make one normal, promote it, or set or remove a `delegate_scope` (the privacy lint blocks the commit).
  - **Health** says when items have waited over a week (`delegate.inbox_waiting`). Runs can't run `inbox review`.
  - **The classifier and the KB index are version 5**, so labels and the privacy index rebuild once after the upgrade. Published labels and the privacy corpus are unchanged.
