- **A recursive search from the vault root filtered to a data format is a KB read** (`engine/scout/kb/raw_read.py`, #541). The `kb-read-gate` hook and the eval's `privacy_hygiene` check share one classifier. It already counted a shell search rooted at the vault or above (`rg x`, `grep -r x .`, `find .`, `ls -R`, `tree`), but let one through when its file filter named any format other than Markdown: `grep -r x . --include='*.yaml'` walked `knowledge-base/` and read the YAML, CSV and JSON files kept there. A filter now keeps a search out of the KB only if it can't match a file in a format the KB keeps facts in: `md`, `markdown`, `yaml`, `yml`, `csv`, `tsv`, `json`, `txt`, and for `rg -t` the types `yaml`, `csv`, `tsv`, `json`, `txt` besides `md`. Still allowed: a search given a folder outside the KB (`rg x scripts/`, `grep -r x .scout-logs --include='*.json'`), a filter that names such a folder (`-g 'scripts/*.yaml'`), a filter for code or logs (`*.py`, `*.sh`, `*.jsonl`, `*.log`), and a search that excludes the KB folders. `rg -tpy` (the type attached to the flag) is now read like `rg -t py`; it was denied before. The Grep and Glob tool rules are unchanged.
  - **This changes what `privacy_hygiene` counts**, so `raw_kb_read` numbers from eval runs scored before this release are not comparable one-to-one with later ones: an earlier run that searched the vault root with a data-format filter was scored as clean on that call.
