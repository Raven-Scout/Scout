- **The changes map, part 1: ledgers and capture.** Nothing reads them yet; the app tab and the digest come later.
  - `scoutctl changes scan [--since] [--backfill]` reads the vault's git history and records Scout's own changes (brain edits, drivers, knowledge-base moves, wishlist items done, rollbacks, upgrades) in a changes ledger, once per commit. The scheduled runners run it after each session.
  - `scoutctl engagement record KIND --surface …` logs owner engagement. `scoutctl engagement consent --out-of-vault yes|no` (or `--show`) answers the consent question. `scoutctl changes --json` and `scoutctl engagement --json` are the contracts the app will read.
  - The owner's store is `~/.local/state/scout/change-map/`, which scheduled runs can't write. A Stop hook records once per session per surface when an owner Claude session relies on Scout. The vault is the installed one (`SCOUT_DATA_DIR`, else the engine pointer's `vault`, else `~/Scout`), never the cwd's, and a session in any git worktree of it counts as in the vault. Sessions outside the vault count only after the owner answers yes.
