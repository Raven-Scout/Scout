- **Delegate inboxes, part one: an agent proposes, the laptop pulls** (#550 V4a1, spec §7.1a; `engine/scout/delegate_inbox.py`, `engine/scout/delegate_proposals.py`). Nothing is applied yet: `inbox apply` is the next PR.
  - `scoutctl delegate inbox <id> --create-repo owner/name` (or `--remote <url>`) links a delegate to its own private inbox repository. Scout binds it by GitHub's numeric repository and owner ids. Before every pull it checks the repository: private, yours alone, not a fork, GitHub Actions and Pages off, and used by no other inbox or mirror. `--create-repo` turns Actions off itself. `--reset` takes the inbox as it is after `inbox_rewritten`, and pushes nothing. `--unlink` forgets the inbox.
  - `scoutctl delegate key <id> --inbox` gives the agent a deploy key titled `scout-delegate-inbox-<id>`. Scout refuses unless GitHub records the key as writable. The mirror key stays read-only.
  - `scoutctl inbox propose observation|action` is the agent's side, and is allowed in a delegate checkout. It writes one proposal, `inbox/<id>/<ULID>.json`, in the agent's inbox clone and commits it there; `--push` pushes it. `scoutctl delegate init --inbox <clone>` tells the agent's setup where that clone is, and the env file remembers it.
  - `scoutctl inbox pull <id>|--all` runs on the owner's computer.
    - **The fetch.** Each pull uses a fresh bare repository outside the vault, and checks nothing out. Git runs with no hooks and with fsck on. It may use only the inbox's own transport, with no submodules, no lazy fetch and no replace refs, under a file-size limit and a timeout.
    - **What it reads.** It reads `main` only, never tags, and filters out blobs over 16 KiB. `main` must build on the last one this computer saw: the pull deepens at most 256 commits to find it, or refuses with `inbox_rewritten`.
    - **The order.** Every proposal is checked strictly. Each one taken is recorded in `.scout-state/delegate-inbox.json`, which is signed and which runs can't write. Then it is copied to `.scout-inbox/agents/<id>/`, and its ULID goes in a `taken.ledger` there. Last, everything taken or refused is removed from the inbox in one compare-and-swap commit.
    - **Limits.** A pull takes at most 50 proposals, and at most 200 a day; the rest stay in the inbox. Nothing is taken twice: not after a crash, nor on another computer.
