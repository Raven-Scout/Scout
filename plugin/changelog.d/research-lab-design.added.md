- **`scoutctl lab` reads and writes research threads, and `kb lint` checks them** (`engine/scout/lab/`). A thread is a front page plus question and experiment files in a vault folder, in a fixed markdown format with fixed headings and status vocabularies. `lab list` and `lab show --json` (schema_version 1) report every thread and every section they can read. The owner and run verbs add comments, answer or drop questions, record evidence, plan experiments and file proposals. Every write takes a per-thread lock and replaces the file atomically, so two writers on one thread both land. A hand-edited front page with a missing or renamed heading still shows, with a problem naming the line, and every write to it refuses and names the heading. Owner comment text that contains the format's own separators or markers is stored as one comment line and reads back unchanged. Private threads are left out of a delegate's `lab list`. The new `lab-format` lint check reports malformed lab files. `scoutctl lab` never commits. Its limits sit under `lab:` in `scout-config.yaml`.
- **The run broker runs experiments in a sandbox with a metered model budget** (`engine/scout/lab/runner.py`, `engine/scout/sandbox/broker.py`). The new `experiment` verb checks that the experiment was announced at least `notice_hours` ahead, that nobody vetoed it, and that it is within the owner's per-run count and cost cap. It then runs the experiment script under a macOS sandbox profile that cannot read private files, with its model calls going through a meter that holds the script to its cost cap. At the timeout the runner kills the script's whole process group and reports `timed_out`, so nothing it started keeps running. The owner's limits live under `"lab"` in the broker's `config.json`. Where the sandbox is unavailable the verb refuses.
