- **`scoutctl lab` reads and writes research threads, and `kb lint` checks them** (`engine/scout/lab/`). A thread is a front page plus question and experiment files in a vault folder, in a fixed markdown format with fixed headings and status vocabularies. `lab list` and `lab show --json` (schema_version 1) report every thread and every section they can read. The owner and run verbs add comments, answer or drop questions, record evidence, plan experiments and file proposals. Every write takes the vault-wide lab lock (`.scout-state/lab.lock`) and replaces the file atomically, so two writers on one thread both land. A hand-edited front page with a missing or renamed heading still shows, with a problem naming the line, and every write to it refuses and names the heading. Owner comment text that contains the format's own separators or markers is stored as one comment line and reads back unchanged. Private threads are left out of a delegate's `lab list`. The new `lab-format` lint check reports malformed lab files. `scoutctl lab` never commits. Its limits sit under `lab:` in `scout-config.yaml`.
- **The run broker runs experiments in a sandbox with a metered model budget** (`engine/scout/lab/runner.py`, `engine/scout/sandbox/broker.py`). The new `experiment` verb checks that the experiment's plan and scripts were committed at least `notice_hours` ago, that nobody ever vetoed it, that it has been started, and that it is within the owner's per-run count and cost cap. A refused request doesn't use up the run's count. It then runs the script as committed at the commit it checked, not the working copy, under a macOS sandbox profile. There the script can write only its own experiment folder, reach the network only through a meter that holds its model calls to the cost cap, and read the vault but not other files in the home folder. An experiment whose note isn't `visibility: private` also can't read private notes or any file of a private thread. No experiment can read another experiment's folder, or the vault's `.scout-state/`, which holds the broker's queue of outgoing commit and Telegram text. The script can't signal or inspect processes outside its own sandbox, and each file it writes is capped at the run's byte cap (at most 1 GiB), with at most `max_open_files` open descriptors (default 1024). It may have at most `max_processes` processes at once (default 64, itself included), counted against the owner's own process count at launch rather than as an absolute per-user limit, and its folder with its scratch dir, plus any file it keeps open after deleting it, may hold at most `max_total_bytes` (default 512 MiB); past either the runner kills it and the run log records `over_processes` or `over_bytes`. At the timeout, and when it exits, the runner kills the script's process group and every process still holding its sandbox, and reports `timed_out` on a timeout. Only a runner that is itself killed from outside leaves such processes behind. The owner's limits live under `"lab"` in the broker's `config.json`. Where the sandbox is unavailable the verb refuses. The verb is off until the owner sets `"experiments_enabled": true` there; until then it answers `experiment not run: experiments are off in the owner's config` (exit 4). The owner's own session runs experiments without it. The broker also refuses an experiment that an unanswered owner comment holds (on its line, or on a question it lists, at HEAD or in the working copy), and one the owner vetoed: `lab veto` records the veto in the owner's `lab-vetoes.jsonl`, which a run can't write, before it changes any file, so a run that rewrites the note by hand can't undo it. One run of an experiment at a time holds a lock in the owner's folder, and a second is refused as already running; the meter's ledger is locked across processes, so the cap holds there too.
- **A private thread's timeline says `visibility: private` in its own frontmatter**, so delegates don't see it. `lab-format` now requires that line on every markdown file in a private thread, and refuses a `lab.md` that links a private thread.
- **An experiment's folder is private by path** (`engine/scout/defaults/privacy.yaml`): its scripts, outputs and run logs, everything under `knowledge-base/lab/*/experiments/*/`, are private whatever their own frontmatter says (a new `visibility_forced_private` list that a vault's overlay can't change), so no delegate or `elsewhere` reader sees them, even an output that labels itself `visibility: normal`. The experiment's note beside the folder keeps its own label. The lab reads `visibility` with the privacy layer's own parser, so `Private`, `secret` and any other value but `normal` count as private there too. `lab show --json` and `lab list --json` leave out, for a reader who doesn't see everything, each experiment whose note that reader can't see; `lab show` counts them in `private_experiments`.
