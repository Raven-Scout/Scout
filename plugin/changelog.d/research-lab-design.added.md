- **`scoutctl lab` reads and writes research threads, and `kb lint` checks them** (`engine/scout/lab/`). A thread is a front page plus question and experiment files in a vault folder, in a fixed markdown format with fixed headings and status vocabularies. `lab list` and `lab show --json` (schema_version 1) report every thread and every section they can read. The owner and run verbs add comments, answer or drop questions, record evidence, plan experiments and file proposals. Every write takes a per-thread lock and replaces the file atomically, so two writers on one thread both land. A hand-edited front page with a missing or renamed heading still shows, with a problem naming the line, and every write to it refuses and names the heading. Owner comment text that contains the format's own separators or markers is stored as one comment line and reads back unchanged. Private threads are left out of a delegate's `lab list`. The new `lab-format` lint check reports malformed lab files. `scoutctl lab` never commits. Its limits sit under `lab:` in `scout-config.yaml`.
- **The run broker runs experiments in a sandbox with a metered model budget** (`engine/scout/lab/runner.py`, `engine/scout/sandbox/broker.py`). The new `experiment` verb checks that the experiment's plan and scripts were committed at least `notice_hours` ago, that nobody ever vetoed it, that it has been started, and that it is within the owner's per-run count and cost cap. A refused request doesn't use up the run's count. It then runs the script as committed at the commit it checked, not the working copy, under a macOS sandbox profile. There the script can write only its own experiment folder, reach the network only through a meter that holds its model calls to the cost cap, and read the vault but not other files in the home folder. An experiment whose note isn't `visibility: private` also can't read private notes or any file of a private thread or private experiment. The script can't signal or inspect processes outside its own sandbox, and files it writes are capped at 1 GiB. At the timeout, and when it exits, the runner kills the script's process group and every process still holding its sandbox, and reports `timed_out` on a timeout. Only a runner that is itself killed from outside leaves such processes behind. The owner's limits live under `"lab"` in the broker's `config.json`. Where the sandbox is unavailable the verb refuses.
- **A private thread's timeline says `visibility: private` in its own frontmatter**, so delegates don't see it. `lab-format` now requires that line on every markdown file in a private thread, and refuses a `lab.md` that links a private thread.
