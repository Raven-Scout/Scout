- **Changelog entries are per-PR fragment files, so merging one PR no longer makes every other open PR conflict** (`changelog.d/README.md`, `engine/scout/scripts/changelog.py`, `scripts/release.sh`). A PR adds `plugin/changelog.d/<branch-slug>.<section>.md` and/or `apps/macos/changelog.d/<branch-slug>.<section>.md` holding its entry's bullets, instead of editing `## [Unreleased]`. `scripts/release.sh prepare` writes them into the new `## [X.Y.Z]` section, grouped by heading, after any entries still under `[Unreleased]`, and deletes them in the release commit; release notes, `rc` and `finalize` are unchanged. The `contract` job runs `python -m scout.scripts.changelog check`: every fragment must parse (a known section, `- ` bullets, no headings), a PR may not change a fragment main already has, and it may not change a `## [X.Y.Z]` section main already has, which is how a merge of main after a release used to file an entry under the release just cut. A PR into `release/vX.Y.Z` may edit `[X.Y.Z]` (and may not add a fragment, which would never reach X.Y.Z), and a `Changelog-Edit-Released: X.Y.Z <why>` commit trailer allows a deliberate fix to that version's section. `.github/scripts/version-bump-only.sh` counts deleted fragments as part of a release bump, so release PRs still skip the heavy suites.
