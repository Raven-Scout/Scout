- **Changelog entries are per-PR fragment files, so merging one PR no longer makes every other open PR conflict** (`changelog.d/README.md`, `engine/scout/scripts/changelog.py`, `scripts/release.sh`). A PR adds `plugin/changelog.d/<branch-slug>.<section>.md` and/or `apps/macos/changelog.d/<branch-slug>.<section>.md` holding its entry's bullets, instead of editing `## [Unreleased]`. `scripts/release.sh prepare` writes them into the new `## [X.Y.Z]` section, grouped by heading, after any entries still under `[Unreleased]`, and deletes them in the release commit; release notes, `rc` and `finalize` are unchanged. The `contract` job runs `python -m scout.scripts.changelog check`: every fragment must parse (a known section, `- ` bullets, no headings), and a PR may not change a `## [X.Y.Z]` section main already has, which is how a merge of main after a release used to file an entry under the release just cut. A `Changelog-Edit-Released:` commit trailer allows a deliberate fix.
