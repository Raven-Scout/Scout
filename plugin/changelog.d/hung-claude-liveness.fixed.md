- **A hung claude behind a live runner shell is no longer taken for a working one** (review of #701; `engine/scout/run_progress.py`, `templates/scripts/scout-lock.sh.tmpl`). The lock reaper counted any write to the run log as progress, but `claude -p` writes nothing until it exits, and on a vault linked to Agnes the lease keepalive appends a line every five minutes for as long as the runner shell lives. So a claude that hung while its shell lived was never judged wedged, and kept the session lock (and every later slot) until something else ended it.
  - **A progress watcher beside every run.** Once a run holds the session lock, `scout-lock.sh` starts `scoutctl progress watch`, on every vault, linked or not. Every `SCOUT_PROGRESS_SAMPLE_SECS` (default 60) it samples the runner's session the way the reaper does, but without Scout's own helpers: the lease keepalive, the run brokers, the watcher itself, and anything they start. The session made progress when it burned `SCOUT_LOCK_PROGRESS_CPU_SECS` (default 10) of CPU or started or ended a process, such as a tool call. The watcher writes how long, in awake time, the session has gone without progress to `.scout-logs/.scout-session.lock.alive` after each sample. It stops on the run's EXIT trap; if the runner is killed it sees the PID gone and removes its line, and a reap takes it with the session's process group.
  - **The reaper reads that line.** While the holder's line is fresh, its stall is the stall, and the holder is reaped once it passes `SCOUT_LOCK_MAX_AGE_SECS` (7200 s of awake time), with no baseline sample needed. Without a fresh line (a runner from before this release, or a watcher that died) waiters sample CPU and the process list themselves as before, but the run log no longer counts. The lease keepalive is unchanged: it still renews the lease and still logs each renewal.
  - **Run health says so too.** `scoutctl health` reports `session.no_progress` (yellow) when the live lock holder's fresh line shows a stall past the same ceiling: the line and the threshold the reaper uses.
  - Existing vaults pick up the runner change with `/scout-update`. Until then, their runs keep the old rule. The run timeout (`agent-runtime exec`) is still off for Claude Code, so the reaper and the app's "Didn't finish" are what bound a hung run.
