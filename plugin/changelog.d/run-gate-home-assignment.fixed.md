- **A scheduled run's shell command can no longer point HOME elsewhere to write a protected file unseen** (`engine/scout/kb/live_run.py`, `engine/scout/hooks/kb_read_gate.py`, `hooks/prefilter.sh`). The write gate expands `~` and `$HOME` with the run's own HOME, so a command that changed HOME first wrote paths the gate never checked: `HOME=~/.local/state/scout ; echo x >> ~/run-limits.json`, `export HOME=… ; cp /dev/null ~/…`, `HOME=… sh -c 'echo x > $HOME/…'`. On macOS the OS sandbox still refused the write; on Linux, which has no kernel layer, nothing did. A run's Bash call is now denied, with its own reason, when it sets, appends to, unsets or reads into HOME, in any form the gate reads: `HOME=… cmd`, `HOME+=…`, `HOME[…]=…`, `export`/`declare`/`typeset`/`local`/`readonly`/`integer HOME=…`, `local HOME`, `env HOME=…`, `env -u HOME`, `unset HOME`, `for`/`select HOME in …`, `read HOME` (also after `IFS=`), `printf -v HOME`, `getopts`, `vared`, `let HOME=…`, a `declare -n` alias of HOME, `${HOME:=…}` and zsh's `${HOME::=…}`, behind `sudo`, `noglob`, `nocorrect` or `-`, inside `sh -c` and `eval`, and with the name quoted or escaped (`HO''ME=…`, `H\OME=…`). So is a builtin given a name built at run time (`export $v=…`, `read $v`, `printf -v "$v"`, `eval "$v=…"`, `${(P)v::=…}`), which may be HOME. `HOME=$HOME` and `HOME=~`, which leave HOME as it is, are still allowed, as are reading `$HOME` and `~`. Setting `XDG_CONFIG_HOME` before a command, or exporting it, is denied as a hook redirect, like `GIT_CONFIG_*`: git reads `$XDG_CONFIG_HOME/git/config`, which can set `core.hooksPath`. The shell pre-filter sends to Python every run command that mentions HOME, or gives such a builtin a `$` name. Its last match now finds HOME, `SCOUT_MODE` and `SCOUT_READER` with quotes and backslashes removed, so `export SCOUT_MO''DE=x` no longer exits in the shell either. Replayed against the last 280 scheduled sessions, no run command is newly denied. Owner sessions are never gated.
