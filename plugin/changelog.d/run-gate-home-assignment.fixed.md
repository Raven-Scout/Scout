- **A scheduled run's shell command can no longer point HOME elsewhere to write a protected file unseen** (`engine/scout/kb/live_run.py`, `engine/scout/hooks/kb_read_gate.py`, `hooks/prefilter.sh`). The write gate expands `~` and `$HOME` with the run's own HOME, so a command that changed HOME first wrote paths the gate never checked: `HOME=~/.local/state/scout ; echo x >> ~/run-limits.json`, `export HOME=… ; cp /dev/null ~/…`, `HOME=… sh -c 'echo x > $HOME/…'`. On macOS the OS sandbox still refused the write; on Linux, which has no kernel layer, nothing did. A run's Bash call is now denied, with its own reason, when it sets, appends to, unsets or reads into HOME, in any form the gate reads: `HOME=… cmd`, `HOME+=…`, `HOME[…]=…`, `export`/`declare`/`typeset`/`local`/`readonly`/`integer HOME=…`, `local HOME`, `env HOME=…`, `env -u HOME`, `unset HOME`, `for`/`select HOME in …`, `read HOME` (also after `IFS=`, and past read's option values; typeset's number options too), `mapfile`, `printf -v HOME`, `getopts`, `vared`, `let HOME=…`, `(( HOME = … ))`, a `declare -n` alias of HOME, `${HOME:=…}` and zsh's `${HOME::=…}`, behind `sudo`, `noglob`, `nocorrect` or `-`, inside `sh -c` and `eval`, and with the name quoted or escaped (`HO''ME=…`, `H\OME=…`). So is any such builtin or assignment whose target is not a plain name, since the shell may turn it into HOME: built at run time in whole or in part (`export $v=…`, `export H$v=…`, `read $v`, `printf -v "$v"`, `eval "H${v}=…"`, `${(P)v::=…}`) or by a glob (`read HOM?` with a file named HOME). `HOME=$HOME` and `HOME=~`, which leave HOME as it is, are still allowed, as are reading `$HOME` and `~` and read's own option values (`read -t $T ans`, `read -p "$prompt" ans`). `XDG_CONFIG_HOME` goes through the same checks and is denied as a hook redirect, like `GIT_CONFIG_*`: git reads `$XDG_CONFIG_HOME/git/config`, which can set `core.hooksPath`. So do `SCOUT_MODE` and `SCOUT_READER` (`read SCOUT_MODE`, `local SCOUT_READER`). The shell pre-filter sends to Python every run command that mentions HOME, or arithmetic, and reads the command a second time with quotes and backslashes removed: there it finds HOME, `SCOUT_MODE` and `SCOUT_READER` (so `export SCOUT_MO''DE=x` no longer exits in the shell either) and, anywhere in the command, one of those builtins, its own name perhaps quoted or escaped (`"read" HOM?`, `\typeset`), which zsh runs as the builtin. zsh's own setters go through the same checks: `print -v`, `zstyle -s/-a/-b/-g`, `zformat -f/-a`, `strftime -s`, `getln`, `repeat N`, a named descriptor (`exec {HOME}>…`), and the module builtins (`zparseopts`, `zstat`, `sysread`, `sysopen`, `zselect`, `zpty`), which are denied any argument that names or builds a name. A `$'…'` string is read as the text its escapes spell, as zsh reads it, so `eval $'\x72ead HOM?'`, `$'\162ead' HOM?` and `eval $'git commit --no-veri\x66y'` are judged as `read HOM?` and `--no-verify`; and `print` or `printf` with an option built at run time (`print -$x HOM?`, which may be `-v` or `-vHOME`) is denied. Replayed against the last 280 scheduled sessions, no run command is newly denied. Owner sessions are never gated.
