- **A scheduled run's shell command can no longer point HOME elsewhere to write a protected file unseen** (`engine/scout/kb/live_run.py`, `engine/scout/hooks/kb_read_gate.py`, `hooks/prefilter.sh`). The write gate expands `~` and `$HOME` with the run's own HOME, so a command that assigned HOME first wrote paths the gate never checked: `HOME=~/.local/state/scout ; echo x >> ~/run-limits.json`, `export HOME=… ; cp /dev/null ~/…`, `HOME=… sh -c 'echo x > $HOME/…'`. On macOS the OS sandbox still refused the write; on Linux, which has no kernel layer, nothing did. A run's Bash call that sets, exports, unsets or reads into HOME (`HOME=… cmd`, `sudo HOME=… cmd`, `export`/`declare`/`local`/`readonly HOME=…`, `env HOME=…`, `env -u HOME`, `unset HOME`, `for HOME in …`, `read HOME`, `printf -v HOME`, a `declare -n` alias of HOME), in any form the gate reads, including `sh -c` and `eval`, is now denied with its own reason. `HOME=$HOME`, which leaves HOME as it is, is still allowed, as are reading `$HOME` and `~`. The shell pre-filter (`hooks/prefilter.sh`) now sends every run command that mentions HOME to Python. Replayed against the last 280 scheduled sessions (13,271 Bash calls), no run command is newly denied. Owner sessions are never gated.
