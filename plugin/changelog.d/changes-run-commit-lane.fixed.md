- The changes map no longer takes a run's word for who made a commit. A scheduled run could commit a brain or driver edit with any subject (`fix: …`, `Revert "…"`, `scout-update: …`), and the map filed it as the owner's own work: untested, and never offered for undo. Now `scoutctl sandbox verify`, which runs outside the sandbox after every run, records each commit the run made in the owner-only store (`run-commits.jsonl`, which a sandboxed run can't write), and the map puts those commits in the run's lane whatever their subject. A run whose mode names no lane (manual, respond, a custom slot) gets the new tested `run` lane. As with the integrity check, the owner's own commits from another linked worktree during a run stay interactive under an enforced sandbox. Commits from before this release, and any run whose start snapshot couldn't be taken, are still classified by their subject prefix.
