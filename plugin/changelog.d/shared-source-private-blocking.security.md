- **A note built from someone's shared note can't be passed on any more, whatever the lint mode** (Agnes #6090 §7; `engine/scout/kb/lint_config.py`, `engine/scout/kb/privacy.py`).
  - **Both checks now always block.** `shared-source-private` (a scheduled run making such a note normal) and `shared-source-reshared` (such a note in a shared file) were blocking findings, but they weren't on the privacy list, so they refused a commit only where `kb_lint` ran in `block` mode. In the default `report` mode they printed and let the commit through. Now they refuse in every mode, like the other privacy checks, and `SCOUT_LINT_OVERRIDE` doesn't apply to them.
  - **Never federated.** A note whose `source:` names a shared note (`shared:<owner>:<path>`) gets federation ceiling `none`. A folder default can't share it even when it is `visibility: normal`, so a note flipped to normal no longer reaches the people a folder is shared with. The classifier is version 6: labels and the privacy index rebuild once.
  - **Which vaults may start blocking.** Only vaults with a note whose frontmatter carries `source: shared:…` and that isn't private. Such a vault now gets its commit refused when a scheduled run makes that note normal, or when the note sits in a shared file or declares a `federation_scope`. Your own commit is refused too when such a note has no `visibility:` line in a folder that defaults to normal: add `visibility: private`, or `visibility: normal` if you mean it, which only warns. A vault with no `shared:` sources sees no change.
