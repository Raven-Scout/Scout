- **A run whose claude has hung shows "Didn't finish", even while the lease keepalive keeps writing its log** (review of #701; `Scout/Services/RunProgress.swift`, `SessionLogService`). Since #701 a running run stayed Running as long as its log was written recently, and on a vault linked to Agnes the lease keepalive writes it every five minutes whether or not claude does anything. The app now reads the line the engine's progress watcher keeps in `.scout-logs/.scout-session.lock.alive`: how long, in awake time, the run has gone without burning CPU or starting or ending a tool. While that line is fresh and names the run's log, the run is "Didn't finish" once that stall passes its type's cutoff, and a slow run that keeps working stays Running however long its log is quiet. A run that stalled and then resumed is Running again at the next sweep, since claude writes nothing to its log for a file event to catch. The line is read without following a link or blocking on a FIFO, at most 4 KB, and trusted for at most 630 s and never with a future time, so a run can't forge itself alive. The engine's lock reaper and `scoutctl health` read the same line against the same rule. The "Didn't finish" problem now says that the engine stops a stuck run after 2 hours without progress, since the app gives up sooner (20 minutes to 2 hours by run type). Without a line (a vault whose runners predate it, until `/scout-update`) the app keeps #701's rule.
