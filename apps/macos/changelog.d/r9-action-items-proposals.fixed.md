- **Topics: a legend filter no longer pins every topic open** (`Scout/ActionItems/TopicBoard/TopicBoardView.swift`, `BoardExpansion.swift`). Topics still open when you pick a state, but their chevrons work again: a topic you close stays closed until the filter changes. The × on an Inbox or Loose ends entry is always drawn, faint until hovered, and its tooltip says Edit ▸ Undo can usually bring the entry back.
- **Settings ▸ Action Items ▸ Done range now changes the Topics board** (`TopicBoardView.swift`, `ActionItemsView.swift`). The board kept its own copy of the range, so the setting did nothing. Both now read and write `actionItems.topics.doneRange` in `scout-display.json`; clicking the range above the Done list changes the setting too. A range picked on the board before this update moves into the profile once, unless Settings already holds a different one. If saving fails (permissions, a full disk), the old range is kept and the next launch tries again.
- **An older day's Topics board shows that day as it stood** (`TopicBoard.referenceDate`). Snoozes and the Done list's "today" and "yesterday" were judged against the real today, so a task snoozed to the next day looked active. They are now judged against the end of the displayed day.
- **Snooze presets count from the real today** (`Scout/ActionItems/Views/SnoozePopoverView.swift`, `SnoozeDates`). On an older day's file, "Tomorrow" counted from that file's day was already in the past.
- **Proposal statuses are read the way dreaming runs write them** (`Scout/Proposals/Models/ProposalStatus.swift`). A leading emoji or `**` no longer hides the status word (`✅ Approved (…)`). `Superseded`, `Withdrawn` and `Obsolete` count as resolved, and `Partially applied` as applied. A status Scout still doesn't recognise used to be filed under Resolved, out of sight. It now stays with the undecided ones and counts toward the sidebar badge. Its card says Scout doesn't recognise it and to read the proposal first, and Approve is not the primary button there.
