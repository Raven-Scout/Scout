- **Action Items works from the keyboard** (`Scout/ActionItems/ActionItemsKeyboard.swift`, UI audit #50). In the List, ↑ ↓ Home End move a highlighted current card, Return or Space opens and closes it, ⌘↵ marks it done and Esc lets go. A click on a card makes it current, and a click on its header gives the list the keys. They act only while the list itself has focus, so Return or Space typed into a comment stays in the comment. The current card follows its own task when a write renumbers the list. Right-clicking a card offers Mark Done or Reopen, Snooze, Expand or Collapse, Copy and Copy As; the writes are off while the engine check fails, like the card's buttons.
- **Schedules rows answer the arrow keys** (`Scout/Schedules/SchedulesMasterTable.swift`, UI audit #57). In the Table and Cards views, a click on a schedule gives the list the keys, and ↑ ↓ Home End then move the selection and scroll it into view (in Cards, in reading order).
- **Knowledge Base: find in a note, and a tree you can drive from the keyboard** (`Scout/KnowledgeBase/Views/KBFind.swift`, `KBTreeView.swift`, UI audit #77). ⌘F finds in the open note: Rich and Source get the system find bar, and Read (the web reader) gets a find bar with ⌘G and ⇧⌘G. ⇧⌘F searches every note, as ⌘F does when no note is open. In the tree (a click gives it the keys), ↑ ↓ Home End move and open notes, → opens a folder and steps into it, ← closes it or steps out, and Return toggles a folder; a note opened from a link or search opens the folders that hold it. Source mode is now a plain text view of its own, since `TextEditor` has no find bar on macOS.
