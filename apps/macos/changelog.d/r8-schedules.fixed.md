- **Schedules speak plainly, and Run now and Save show their progress** (UI audit R8, findings #55, #56, #58; `Scout/Schedules/SlotDraft.swift`, `Scout/Schedules/SlotEditForm.swift`, `Scout/Schedules/SchedulesView.swift`). Field errors use the form's own names ("Wait between runs can't be less than 0 minutes", "Catch-up window must be at least 1 hour", "Script can't be empty") instead of "Runner", "Cooldown" and "Missed window". When Save is off because of a field, the reason shows under the buttons, including one in the collapsed Advanced group. Save shows "Saving…" and locks the form until it finishes. Run now shows "Starting…", and a run that doesn't start gets a banner with the engine's words under Details; before, the page said nothing. When the schedule can't load, scoutctl's output also moved behind Details.
- **A schedule's time is a time picker, and a new schedule can't take an existing name** (#58). The picker follows your clock format and always writes `HH:MM`, so "8:00" without a leading zero can't be typed any more. A new schedule named like an existing one is refused in the form, and the save path refuses any write with two schedules under one name: the engine keeps only the last of two, so the other was silently replaced.
- **The Schedules timeline shows one day at a time** (#60; `Scout/Schedules/SchedulesTimelineView.swift`). It opens on today, with a picker for each weekday and "Every day". A weekday-only schedule no longer appears on Saturday, and the "now" line shows only on today.
- **The Schedules page follows schedule.yaml** (#61; `Scout/Services/ScheduleEditService.swift`). When the file changes outside the app (by hand, a sync, another tool), the page reloads it within a second. Unsaved edits are kept: an open form keeps your values, takes the file's values for fields you didn't touch, and names any field changed on both sides. A reload waits for a save in progress, and the app's own saves don't trigger a second reload.
