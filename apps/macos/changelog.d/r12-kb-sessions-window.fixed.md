- **Renaming a knowledge-base note no longer breaks the links to it** (`Scout/KnowledgeBase/Models/KBLinkRewrite.swift`, `KnowledgeBaseFileWriter.swift`, `Views/KBEditorView.swift`; UI audit #75). The Rename sheet says how many links in how many notes point to the note, with "Update N links in M notes" on by default. The links are rewritten the way the vault's `kb-move.sh` does it: an alias, a heading anchor, an explicit `.md`, a folder path and the table-cell `\|` form are kept as written. If another note already has the new name, a bare link is written as a path, so it can't point to the wrong note. Each linking note is re-read and rewritten only if it hasn't changed since. A note with unsaved edits in the app is left alone, and the sheet says so beforehand. The rename and every rewritten link go into one commit and one Edit ▸ Undo. Turning the option off says how many links will stop working. A rename that fails now keeps the sheet open with the typed name and the reason, instead of closing it behind a "Couldn't save" alert.
- **Knowledge-base health groups dangling links by the note that holds them** (`Scout/KnowledgeBase/Views/KBStatsView.swift`, `Models/KBGraph.swift`; UI audit #73). The section heading reads, for example, "40 dangling links in 3 notes" instead of listing every link, and each row shows the note (click to open it), its count and its first few missing targets, with the note holding the most broken links first. Each health and insight figure has a one-line explanation of what it means and what to do about it.
- **The Knowledge Base says it's loading instead of going blank** (`Scout/KnowledgeBase/Views/KnowledgeBaseView.swift`, `KBOverviewView.swift`; UI audit #76). While the first scan runs, the tree and the overview show "Loading notes…", where the tree used to be empty and the header read "0 notes · 0 links" over a map saying "No notes yet". Coming back to the page keeps the tree on screen while it rescans, where it used to blank it each time.
- **Session cards name their state** (`Scout/Sessions/Views/SessionCardView.swift`, `SessionStatePill.swift`; UI audit #35). Each card on the Sessions board starts with its state in words and a symbol of its own, such as "Needs you", "Running" or "Parked", beside its age. Before, a 3 pt coloured edge was the only sign, which didn't help anyone who can't tell the colours apart.
- **An empty Sessions page says why** (`Scout/Sessions/Models/SessionsLayout.swift`, `Views/SessionsBoardView.swift`, `SessionsView.swift`; UI audit #37). A first run with no sessions now reads "No Claude Code sessions yet", where it used to say "No sessions match these filters." When every session is one of Scout's own runs or finished, the page says they're hidden and which View options show them. Filters that match nothing get a "Clear filters" button. The table view shows the same message instead of an empty grid.
