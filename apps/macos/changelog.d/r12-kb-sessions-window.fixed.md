- **Renaming a knowledge-base note no longer breaks the links to it** (`Scout/KnowledgeBase/Models/KBLinkRewrite.swift`, `KnowledgeBaseFileWriter.swift`, `Views/KBEditorView.swift`; UI audit #75). The Rename sheet says how many `[[wikilinks]]` in how many notes point to the note, with "Update N links in M notes" on by default. Turning it off says how many links will stop working.
  - Only the name in each link changes. An alias, a heading anchor, an explicit `.md`, a folder path and the table-cell `\|` form stay as written. The note's own links to itself are updated too.
  - When more than one note has the old name, a bare `[[name]]` can't be told apart, so it's left as it is and the sheet says how many there are. When another note already has the new name, the sheet warns that its links may switch, and a bare link is written as a path.
  - Each linking note is re-read just before it's written, and written only if it still holds what was read. A note with unsaved edits in the app, one that changed meanwhile, or one that can't be read or written is left alone, and named afterwards with the reason.
  - The rename and every rewritten link land in one commit and one Edit ▸ Undo step. Undo works as long as none of those notes has changed since. If the commit fails, for example while a scheduled run holds git's lock, the undo step and the list of notes left alone are still there, next to the commit error.
  - Markdown links (`[text](note.md)`) aren't changed.
- **A note keeps being a note when its new name has a dot** (`Scout/KnowledgeBase/KnowledgeBaseFileWriter.swift`). Renaming a note to `acme.com`, `vue.js` or `v2.1` used to create a file with no `.md`, which dropped out of the knowledge base. It now becomes `acme.com.md`. A note's name also can't contain `#`, `|`, `[`, `]` or `^`, since links use those characters, and the sheet says so as you type.
- **A failed rename keeps the sheet open** (`Scout/KnowledgeBase/Views/KBEditorView.swift`). The typed name stays, with the reason under it. Before, the sheet closed behind a "Couldn't save" alert.
- **Knowledge-base health groups dangling links by the note that holds them** (`Scout/KnowledgeBase/Views/KBStatsView.swift`, `Models/KBGraph.swift`; UI audit #73). The section heading reads, for example, "40 dangling links in 3 notes" instead of listing every link, and each row shows the note (click to open it), its count and its first few missing targets, with the note holding the most broken links first. Each health and insight figure has a one-line explanation of what it means and what to do about it.
- **The Knowledge Base says it's loading instead of going blank** (`Scout/KnowledgeBase/Views/KnowledgeBaseView.swift`, `KBOverviewView.swift`; UI audit #76). While the first scan runs, the tree and the overview show "Loading notes…", where the tree used to be empty and the header read "0 notes · 0 links" over a map saying "No notes yet". Coming back to the page keeps the tree on screen while it rescans, where it used to blank it each time.
- **Session cards name their state** (`Scout/Sessions/Views/SessionCardView.swift`, `SessionStatePill.swift`; UI audit #35). Each card on the Sessions board starts with its state in words and a symbol of its own, such as "Needs you", "Running" or "Parked", beside its age. Before, a 3 pt coloured edge was the only sign, which didn't help anyone who can't tell the colours apart.
- **An empty Sessions page says why** (`Scout/Sessions/Models/SessionsLayout.swift`, `Views/SessionsBoardView.swift`, `SessionsView.swift`; UI audit #37). A first run with no sessions now reads "No Claude Code sessions yet", where it used to say "No sessions match these filters." When the view options hide every session, the page says so and names only the options that are still off. With both on, it says the sessions finished longer ago than the recently-done window. Filters that match nothing get a "Clear filters" button. The table view shows the same message instead of an empty grid.
