# Changelog — Scout for macOS

Scout's app and plugin share one version and one release (`vX.Y.Z`), cut with `scripts/release.sh`. Each
release's notes combine this file's section with [`plugin/CHANGELOG.md`](../../plugin/CHANGELOG.md).
Keep an `## [Unreleased]` section at the top. `scripts/release.sh prepare` promotes it.

## [0.18.17] - 2026-11-18

### Added
- **One set of button styles: the start of design-system v2** (UI audit card R6, #105; `Scout/Utilities/DSButtonStyle.swift`, `Scout/Utilities/DSPalette.swift`, `Scout/Utilities/PlainHitButtonStyle.swift`). `.dsPrimary` (filled accent), `.dsSecondary` (raised paper with a hairline), `.dsLink` (accent text) and `.dsDestructive` (red label), each at a regular or small size. The style draws the font, colours, padding and the disabled, pressed and keyboard-focus states, so a disabled button looks disabled the same way everywhere. Every label-on-fill pair is in `DS.ContrastPairs`, so `ContrastPairsTests` checks it in light, dark and Increase Contrast. `ButtonStyleGuardTests` flags new system bordered/link buttons and accent buttons hand-built from `.plainHit`; an icon button or chip marks its line `// ds-guard: hit area`. `.plainHit` stays for hit areas (chips, segments, rows, icon buttons).
- **The Knowledge Base tab, rebuilt around a map you can explore** (`Scout/KnowledgeBase/Web/*`, `Views/KBMapWebView.swift`, `Views/KBReaderWebView.swift`, `Views/KBOverviewView.swift`, `Models/KBMapPayload.swift`, `Models/KBReaderDocument.swift`). The map and the note reader now run in a `WKWebView` from pages and scripts bundled with the app (d3-force, markdown-it, DOMPurify, highlight.js; versions and licences in `Web/KB-WEB-LICENSES.md`). Nothing is loaded from the network, and both pages carry a content-security policy.
  - **The overview is the map.** A slim header (note and link counts, quick links to the hub notes, a Map | Health switch) sits over a full-page map of every note, not 40 of them. Notes are coloured by type, and the types now follow the vault's layers: Topics, Sources, Personal, Logs and Audits joined People, Projects, Issues, Channels, Ontology and Research, so most of the vault is no longer one grey "Other". Ontology moved from the dreaming violet, which read the same as People's purple, to indigo. Each type settles into its own region, and the legend's counts hide or show a type (⌥-click shows only that type). Search (`/`) ranks matches, lights them up on the map and flies to the one you pick. Hovering a note lights its links; clicking selects it and opens a side card with its type, folder, link count, when it changed, a summary, its connected notes and Open note. "Only its connections" lays a note's direct links out on rings around it, one ring per type. Freshness colours notes by how recently they changed. A hub's hundreds of links show only when it's hovered or selected, so they don't bury the rest. The layout is seeded from each note's path, so the vault lays out the same way every time, and the settled layout is kept while the app runs, so the map reopens where you left it. Pinch or ⌘-scroll zooms, two-finger scroll pans, double-click opens a note. VoiceOver gets a list of the 60 best-connected notes; Reduce Motion lays the map out before showing it and turns off the moving link dots. The vault-health report moved to the Health switch.
  - **A note's Graph tab uses the same map**, centred on the note, with "Show on full map" to open the overview with it selected.
  - **Comment on any text you select.** In Read mode, select anything — part of a sentence, a table cell, a list item — and a Comment button appears (or press ⇧⌘M). The comment is saved as a Scout marker that quotes the passage, `//==<< on "passage": comment >>==//`, on the line after the block it's in: indented inside a list item, `>`-prefixed inside a quote, after the whole table or code block, so none of them is split. The quoted passage stays highlighted in the note, and hovering a comment highlights its passage. Comments used to be possible only from a hover button under a whole block, never on tables, and said nothing about which words they meant.
  - **Notes render properly.** markdown-it replaces the line-by-line renderer, so wrapped and nested list items, code inside lists, `<details>`, task checkboxes (click to tick), callouts (`> [!note]`) and highlighted code all render, and long tables scroll sideways. Frontmatter and the `**Last updated:**` header fold into one "Properties & history" box under the title. Links to notes that don't exist show as missing; ticket ids still open in Linear.
  - Editing in place works as before, now with the web reader: double-click a paragraph, heading, list item, quote, code block or table cell; each keystroke goes into the note's draft; Done, Esc and ⌘↩ close the editor, Discard puts the block back, ⌘S saves.

### Changed
- **Buttons across the app use the new styles** (R6, #105). The problem banner (`ProblemView`), undo and write-problem toasts, Schedules (+ New, Save, Revert, Run now, Delete, Retry, Add schedule, the "changed outside the app" banner), Settings ▸ Budget's Save, Settings ▸ Updates, Action Items (Previous day, Today, Copy, the topic prompt box, Open note), the menu-bar panel's Open and fix buttons, Sessions' PR Open, Wishlist and Research cards' Show more, onboarding and the engine upgrade sheet. Disabled Save and + New now look disabled (they used opacity, or nothing). The topic prompt's Send is the accent, no longer the urgent red. The rebuilt Knowledge Base's Retry, Reload, overview crumb and "Show on full map" and the run detail's Errors tab use them too.
- **CI runs the Xcode 27 ScoutTests leg on pushes to main, no longer on pull requests** (`.github/workflows/app-ci.yml`). The org gets five macOS runners at once on GitHub's free plan. On a PR, this non-blocking leg held one of them while the required ScoutTests job queued behind it, for up to 29 minutes. Every app change still runs on Xcode 27 once it merges.

### Fixed
- **Sessions: Resume opens the session's own folder, and the window doesn't hang while it opens** (UI audit card R4, findings #32 and #36; `Scout/Sessions/SessionResume.swift`, `Scout/Sessions/SessionsFormat.swift`, `Scout/Sessions/Views/SessionDetailView.swift`, `Scout/Utilities/ClaudeLauncher.swift`). `claude --resume` finds a session only from the folder it ran in. Resume now takes that folder from the session's transcript (the index's transcript path, else a search of `~/.claude/projects` by id, as Action Items does), then the index's folder. When the session's own folder is gone it resumes from the project folder and says so under the buttons; when neither exists it says which folder is missing and launches nothing. It used to fall back to the home folder, where Claude never finds the session.
  - Finding `claude` through a login shell, asking tmux for a session and reading the transcript now run off the main thread. Resume shows "Opening…" with a spinner and ignores a second click meanwhile. Action Items' Launch Claude, Resume and the board's prompt box use the same async launcher, and they too ignore a second click while a launch is under way, which used to open two terminals.
  - Copy handoff says "Copied" for two seconds. A disabled Resume says why in its tooltip.
- **Ghostty launch failures are shown, not just logged** (finding #38; `Scout/Utilities/GhosttyLauncher.swift`, `Scout/Utilities/ClaudeLauncher.swift`, `Scout/Utilities/LaunchFailureAlert.swift`, `Scout/ControlCenter/Detail/DiffViewer.swift`). A missing Ghostty, macOS refusing to open it or bring it forward, and System Events refusing keystrokes now reach an alert instead of the system log. When a permission is the cause (Accessibility for Ghostty's new tab, Automation for Terminal or iTerm2), the alert names the pane and has an "Open System Settings" button that opens it. This covers Resume, Launch Claude (whose other errors stay inline on the card) and "Open full diff in Ghostty".
- **A folder name can no longer run a command when Claude opens in a terminal** (`Scout/Utilities/ClaudeLauncher.swift`, `Scout/Utilities/GhosttyLauncher.swift`). The commands for Terminal, iTerm2, a new Ghostty window and a Ghostty tab put the folder and the `claude` path in double quotes, where `$(…)`, backticks and `$VAR` still run. A folder named `proj$(…)` ran that command on Resume or Launch Claude, and any `$` in a folder name sent `cd` to the wrong place. Both are now single-quoted, as the custom command already was; a trailing `\` no longer breaks the Ghostty tab's line either. Tests run each command through the shell on a folder whose name holds `$(…)`, backticks, `$HOME`, quotes and a trailing backslash, and check it lands in exactly that folder.
- **Sessions: "Now" cards aren't repeated in their project's lane** (finding #34; `Scout/Sessions/Models/SessionsLayout.swift`, `Scout/Sessions/Views/SessionsBoardView.swift`, `SessionCardView.swift`). Every needs-you and running card used to show twice. A lane now holds only the cards that aren't in Now, so a project whose sessions are all in Now has no lane; each Now card names its project instead. The table is unchanged.
- **Sessions: two projects with the same name can be told apart** (`Scout/Utilities/PlainLanguage/DisplayName.swift`, `Scout/Sessions/Models/SessionsLayout.swift`). Two lanes could both read "Scout". `DisplayName.projectNames` gives projects that share a name the shortest end of their folder path that differs, with home as `~`: "Scout (~/Scout)" and "Scout (code/Scout)". The lanes, the project menu, the table, the detail pane and the handoff all use it. Search still matches the plain name.
- **Sessions: "PR check: 2 problems" opens the problems** (`Scout/Sessions/Views/SessionsHeader.swift`, `Scout/Sessions/Views/PRCheckProblemsView.swift`). The PR half of the header's freshness line is a button whenever the PR check had a problem. It opens a list of every pull request Scout couldn't check, with when it last checked, "Check again" and "Copy details". The errors used to be only in a tooltip.
- **A run that hit Claude's sign-in race says so** (`Scout/Utilities/PlainLanguage/DisplayName.swift`, `Scout/Utilities/PlainLanguage/Problem.swift`, `Scout/Help/DiagnosticsScrubber.swift`). The engine files a run that started while another Claude Code process was refreshing the sign-in as `failure_class: auth_race`, where it used to be `unknown`. The Health page called it "an error Scout doesn't recognise". It now reads "Claude login was busy", says the login is fine, and shows as a warning, like a network problem: the run is retried. Diagnostics keep the value.
- **Onboarding reads as a first-run flow for a new owner** (R6, #87–#91; `Scout/Onboarding/OnboardingView.swift`, `OnboardingViewModel.swift`, `EngineUpgradeSheet.swift`).
  - Continue, Open Scout and Retry are real primary buttons that look disabled when they are (#87). Return moves on where Continue only moves on. Where it installs the engine or creates the Scout folder, the button says so ("Install engine", "Create Scout folder") and takes a click, so Return in a text field can't set up the Mac.
  - The last step says "Everything checks out", "Ready, with 2 things to look at later" or "Something needs fixing before the first run", with what to do next. The health check's own lines are under Details, no longer "Health: yellow" over a monospaced dump (#88).
  - Each step has a name and a count ("Step 3 of 7 · Install the engine"). Progress uses symbols with a spinner and spoken states, not ○ ✓ ✗. A failed step shows its whole log, selectable, with Copy details. A broken engine is titled "Repair Scout" and says why setup runs again (#89).
  - The Scout folder has a Choose… folder picker, and the time zone is a picker, not free text. The two budget fields move from Connectors to About you, under "Spending limits", named as Settings ▸ Budget names them ("Limit per run", "Daily budget") (#90).
  - The engine upgrade sheet, which opens on its own at launch, says why and that it usually takes a minute or two, shows a spinner on the running step, and on failure offers Copy details, Later and Retry (#91).
- **A failed update check says what went wrong** (R6, #92; `Scout/Shell/UpdatesSettingsSection.swift`). Settings ▸ Updates shows the checker's own message ("Couldn't check the latest plugin version: HTTP 404 from …") under the row, not only "Couldn't check".
- **"Update available" in the menu-bar panel opens Settings at Updates** (R6, #93; `Scout/Shell/MenuBarExtraContent.swift`, `Scout/Help/HelpCommands.swift`, `Scout/Shell/SettingsView.swift`), not at the top of Settings. The Engine-only scroll request now takes any Settings section.
- **A run started in the same minute as another shows as its own run** (`Scout/Services/SessionLogService.swift`, `Scout/Models/Run.swift`, `Scout/Services/ClaudeSessionService.swift`, `Scout/ControlCenter/Detail/FeedbackTab.swift`). The runners now give a later run in the same minute its own log, `<stem>-YYYY-MM-DD_HH-MM-SS-PID.log`, and the app reads it.
  - A run with a minute-named log keeps the id it always had, so saved feedback still matches. A seconds+PID log gets an id with its seconds and PID, and its own feedback file.
  - The run ledger's status reaches each of the two runs from its own row.
  - A skipped run gets no Claude session and no cost. It used to pick up the session and cost of the run it was skipped for, started the same minute.
- **A lock skip no longer marks the running session as orphaned** (`Scout/Services/SessionLogService.swift`). A later run of the same type that finished counted as proof that an earlier `.running` run had died, and a run skipped on the session lock counted too, although it is proof of the opposite: the runner skips there because the lock is held. This happened before unique log names whenever a lock skip landed in a later minute. Lock skips no longer count. Every other skip (budget, privacy checks, write protection, agent runtime, writer lease, redundant) happens after the runner took the lock, so it still counts, as does a later run that succeeded, failed or timed out.
- **The Research tab loads again when an item's `status:` carries a comment** (`Scout/PerFileItems/PerFileItemParser.swift`, `Scout/PerFileItems/Models/PerFileItem.swift`, `Scout/PerFileItems/Views/ItemStatusPill.swift`, `Scout/PerFileItems/Views/PerFileItemCardView.swift`, `Scout/PerFileItems/Models/MarkdownBodyBlock.swift`). On a real vault the tab showed only an empty grey box. A retired research item read `status: done   # retired …`; the app took the whole line as the status, an unknown status counts as active, so the done 220 KB item was listed. Its status pill showed the full comment on one line and pushed the card wider than the window, and the card built all 220 KB of its text.
  - `status`, `priority` and `date` now drop a YAML inline comment (a `#` at the start or after a space). A quoted value keeps its `#`: `"done # pending review"` is not `done`, so the item stays active. Text after a closing quote is a comment (`"done" # retired` is done), and single quotes now count as quoting. Free-text fields such as `title` and `source` keep their `#`, so `Pattern #197` and `C#` read as before.
  - The engine reads a status as its first word. The two agree on plain values with or without a comment. They differ on a value that is only a comment (`status: # TODO`: open here), a status with a space (`in progress`), and quoted values. Tests pin both the cases where they agree and these differences.
  - The status pill shows at most 24 characters; the full value is in its tooltip and what VoiceOver reads.
  - A long card builds only the text it shows: about 1,500 characters collapsed and 20,000 expanded, with a link to open the file past that. Clipping alone hid the rest but still laid it out. An item's body is now split into blocks once when the file is read, not on every redraw.

Research cards showed `>` markers on their own lines, LaTeX-style math as `(\ge 1.5)` and stray `**`. A preamble paragraph without a bold lead was cut at its first `.` or `:`, so "Rewritten by the 09:03 run: …" read "Rewritten by the 09". It now splits only at a `.` or `:` followed by a space, and not at an ellipsis or a common abbreviation ("e.g.", "vs."). Leading `>` and `[!kind]` markers are no longer part of the headline.

Certificates, estimates, warranties and payslips under a `personal` folder now join receipts and invoices on the "Not counted" line, now worded "N paperwork notes". Outside `personal/` those words stay live ("tls-certificate-rotation"). Reports are never set aside. Same rule as `/scout-status`.
